# Anexo tecnico de rendimiento high elo

En la primera versión del sistema, la búsqueda de vehículos por patente se hacía recorriendo una lista completa, lo que generaba una complejidad **O(n)**. En esta nueva versión se utilizó una estructura de acceso directo, como un `Map<String, Vehiculo>`, donde la patente funciona como clave. Esto permite encontrar un vehículo de manera mucho más rápida, con un costo promedio de **O(1)**, evitando recorrer toda la colección cada vez que se necesita una búsqueda.

Para la de duplicación de alertas GPS, una solución ineficiente habría sido comparar cada reporte con todos los demás mediante bucles anidados, lo que produciría una complejidad **O(n²)**. Para evitar ese problema, se utilizó un `Set`, que no admite elementos repetidos. De esta forma, la lista de reportes se recorre una sola vez, logrando una solución de aproximadamente **O(n)** y mejorando notablemente el rendimiento cuando se procesan grandes cantidades de datos.

En el caso del ordenamiento el criterio natural de los vehículos se resolvió con `Comparable`, definiendo la prioridad de carga según el nivel de batería de menor a mayor. A la vez el criterio alternativo de ordenamiento por tarifa base de mayor a menor se implementó con un `Comparator` externo. Esto permite mantener el orden natural del vehículo sin perder la posibilidad de aplicar otros criterios de ordenamiento cuando el sistema lo requiera logrando una solución más flexible y mejor diseñada.
